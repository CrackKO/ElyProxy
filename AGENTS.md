# AGENTS.md

ElyProxy: WPF desktop client (.NET 8, `net8.0-windows`) for VLESS subscriptions on Windows. Runs Xray-core for SOCKS5/TUN and sing-box for the ElyTun full-tunnel mode. UI text is Russian, code comments are English. The folder is `SuperSocks`, but project/namespace/assembly is `ElyProxy`.

## Commands

- Build: `dotnet build ElyProxy.sln`
- Test from repo root: `dotnet test` (111 xunit tests, `tests/ElyProxy.Tests`)
- Focused test: `dotnet test --filter "FullyQualifiedName~SingBoxConfigBuilderTests"`
- Run: `dotnet run` — the client starts unelevated; selecting ElyTun triggers an on-demand UAC prompt and elevated relaunch.
- Local preview build (no installer): `dotnet publish ElyProxy.csproj -c Release -r win-x64 --self-contained false -o publish\redesign-preview`. `publish/` is gitignored; the csproj copies the repo-root `xray/**` runtime files into the output. A running `ElyProxy.exe` locks the folder — exit the app or publish to a new folder.
- Release: bump `Version`, `AssemblyVersion`, `FileVersion` in `ElyProxy.csproj`, then run `.\tools\New-ElyProxyUpdate.ps1 -Version X.Y.Z -ReleaseNotes '...'`. The script fails if the csproj version doesn't match or artifacts for that version already exist; validation lives in `tools/ElyProxyUpdateValidation.ps1` and is covered by Pester tests (`Invoke-Pester -Path tools`). Details in `tools/README.md`.

Publishing the main project also publishes `ElyProxy.Updater` into the `updater/` subfolder (MSBuild `PublishUpdater` target) and `ElyProxy.Helper` into `helper/` (`PublishHelper` target); the self-update and helper-service flows depend on that layout. `ElyProxy.csproj` excludes `tests/**`, `ElyProxy.Updater/**` and `ElyProxy.Helper/**` from its own compilation.

## Layout

- `Core/` — child-process + config generation. `XrayManager`/`SingBoxTunManager`/`SingBoxProxyManager`/`Tun2ProxyManager`/`HysteriaManager` wrap `ProcessManagerRouter` (local `ProcessManager` or `HelperProcessManager` over the ElyProxy.Helper service); `ConfigBuilder` emits Xray JSON, `SingBoxConfigBuilder` emits sing-box JSON, `HysteriaConfigBuilder` emits Hysteria YAML; `RoscomVpnDefaultRouting` is the bundled routing preset; `ProxyProtocolSupport` gates protocol/core combinations; `ServerAddressResolver` resolves node endpoints; `CoreLocator` resolves core binaries.
- `ElyProxy.Helper/` — separate elevated service (`sc`-installed, named pipe `ElyProxyHelper`) that runs the four core executables as SYSTEM so TUN works without UAC; client side is `Core/HelperProcessManager` + `Services/HelperServiceInstaller` (opt-in via `AppSettings.UseHelperService`; status is read through `ServiceController`, never by parsing localized `sc query` output). Published into `helper/` by the `PublishHelper` target.
- `Services/` — storage (`%AppData%/ElyProxy/`), subscription parsing (links, base64, Clash YAML via `ClashYamlParser`, JSON via `JsonConfigParser`), subscription-userinfo and per-subscription settings, PAC HTTP server, Windows proxy registry changes, update check/download, core updater (`CoreUpdateService`/`CoreVersionService`), autostart, port owner lookup, traffic monitor (`TrafficMonitorService` via sing-box Clash API), share/export (`ShareLinkBuilder`, `ClashYamlExporter`, `V2rayNJsonExporter`), helper service installer, plus `ThemeService` (appearance) and `DialogService` (sheets/toasts).
- `ViewModels/MainViewModel.cs` (~100 KB, decompiled) holds essentially all app behavior/commands. It is `partial`; UI-only members live in `ViewModels/MainViewModel.Ui.cs`.
- `Views/MainWindow.xaml` is only the window shell (title bar, sidebar, status bar, log drawer). Screens are `Views/Sections/*.xaml` (servers, subscriptions, profiles, settings) and modal forms are `Views/Sheets/*.xaml`. There are four sections; `Ctrl+1..4` switch them.
- `Theme/` — the design system: `Tokens.Light.xaml`/`Tokens.Dark.xaml`/`Tokens.HighContrast.xaml` (swapped at runtime), `Typography.xaml`, `Converters.xaml`, `Controls/*.xaml` (buttons, inputs, lists, menus, surfaces, shell).
- `Controls/` — custom controls and the motion engine: `Motion/SpringAnimator.cs` (frame-driven springs), `Motion/MotionPreferences.cs` (reduced motion/transparency), `SegmentedControl`, `ModeSelector`, `SpringToggleSwitch`, `EmptyState`, `SkeletonList`, `BusyRing`, `SheetHost`, `ToastHost`, `Behaviors/SmoothScroll.cs`, `Converters/`.
- `Interop/` — `WindowChromeHelper.cs` (Snap Layouts hit-testing on Windows 11, caption dragging) and `WindowBackdropInterop.cs` (DWM Mica/Acrylic).
- `ElyProxy.Updater/` — separate WinForms exe that replaces files after the client exits and restarts it.
- `deployment/elyaxis-staging/` — unrelated Telegram bot / Laravel staging files, not part of the C# build.

## Protocols & cores

- Node model is `Models/VlessNode` (name kept for compatibility) with `Protocol` = `vless`/`vmess`/`trojan`/`shadowsocks`/`hysteria2`/`tuic`/`anytls`/`ssh`/`wireguard`/`naive`/`shadowtls`/`socks`/`http`; protocol-specific fields live in `VlessNode.Extra` (`GetExtra`/`SetExtra`). `Services/ParserService` parses links (`vless://`, `vmess://` base64 JSON, `trojan://`, `ss://` SIP002+legacy, `hysteria2://`/`hy2://`, `tuic://`, `anytls://`, `ssh://`, `naive://`/`naive+https://`, `http(s)://` with credentials), base64-wrapped lists, **Clash YAML** (`Services/ClashYamlParser`, YamlDotNet) and **JSON configs** (`Services/JsonConfigParser`: Xray `outbounds[].protocol`, sing-box `outbounds[].type` incl. ss→shadowtls detour pairing, Clash `proxies`, and **arrays of full Xray/sing-box configs** — names come from `remarks`, duplicates are removed); `ParseUri` is the generic entry point.
- Capability routing: VLESS (Reality, WS/CDN, gRPC, HTTPUpgrade, xhttp, mKCP, VLESS Encryption), VMess, Trojan and Shadowsocks run on both Xray and sing-box; Hysteria2/TUIC/AnyTLS/SSH/WireGuard/NaiveProxy/ShadowTLS are sing-box-only (WireGuard uses the `endpoints` array, ShadowTLS chains a `detour` ss outbound) and VLESS Encryption is Xray-only. `Core/ProxyProtocolSupport` decides (including `libcronet.dll` presence for naive) and the view model refuses to connect with a dialog instead of generating an invalid config.
- TUN cores: `AppSettings.TunCore` (`TunCoreKind`) picks `sing-box` (default), `Xray` (native `tun` inbound, single process), `tun2proxy` (TUN over the local SOCKS/mixed backend: `--setup --dns virtual`, bypass = node endpoint + direct CIDRs) or `Hysteria` (Hysteria 2 built-in TUN, hysteria2 nodes only). The tun2proxy backend is Xray for Xray-capable nodes, sing-box otherwise (or the Hysteria core for hysteria2 nodes when `AppSettings.Hysteria2Engine = Hysteria`).
- DPI evasion: `AppSettings.FragmentMode` (Off/Auto/Custom) plus `FragmentPackets/Length/Interval`, `FragmentRecord` (sing-box `tls.record_fragment`), `NoiseType/Packet/Delay` (Xray freedom `noises`), and `TlsSpoofEnabled/TlsSpoofSni/TlsSpoofMethod` (sing-box `tls.spoof`/`spoof_method`, TLS only, needs admin). Xray chains the proxy outbound through a `fragment` freedom outbound via `sockopt.dialerProxy`; sing-box uses `tls.fragment`/`fragment_fallback_delay`. Per-app routing (`AppSettings.PerAppMode` Bypass/OnlySelected) is emitted as a `process`/`process_path` rule before domain rules for Xray/sing-box (in OnlySelected mode Xray also sends selected apps' DNS via the proxy); selecting OnlySelected with an empty app list or a core without per-app support is refused with a dialog. tun2proxy has no per-app support.
- Core management: `Core/CoreLocator` resolves each core from `%LocalAppData%/ElyProxy/cores/<id>/` first, then the app folder (`xray/`, `sing-box/`, `tun2proxy/`, `hysteria/`) and `bin/`. `Services/CoreUpdateService` downloads GitHub release assets (Xray, sing-box incl. `libcronet.dll`, tun2proxy, Hysteria 2), verifies SHA-256 when the API provides a digest, backs up existing files and rolls back if `<core> version` fails after install; `Services/CoreVersionService` runs `<core> version`. UI: Settings → Ядра.
- Monitoring & helper: sing-box configs expose a Clash API (`XrayTunOptions.ClashApiPort`/`ClashApiSecret`, port picked dynamically) that `TrafficMonitorService` polls for up/down speed and session totals (status bar). The optional ElyProxy.Helper service (Settings → ElyTun → Служба-помощник) runs cores as SYSTEM through the `ElyProxyHelper` named pipe, so TUN needs no UAC. All ElyTun elevation gates (`RequestElyTunAsync`, the `ElyTunEnabled` setter, `EnsureElyTunCanRun`, startup restore) go through `MainViewModel.CanRunElyTunWithoutElevation()`, which delegates to `Services/ElyTunAvailabilityPolicy` (admin **or** (`UseHelperService` && helper service running); covered by `ElyTunAvailabilityPolicyTests`); don't add raw `IsRunningAsAdministrator()` checks.
- Subscriptions: `SubscriptionService` sends a per-subscription User-Agent (presets in `Services/UserAgentCatalog`: Happ, v2rayN, Shadowrocket, ...), optional `X-Hwid` and custom HTTP headers (`Services/SubscriptionHeaderParser`), and parses `subscription-userinfo` (traffic/expiry); the view model notifies once when traffic usage crosses 80% or expiry is within 3 days (flags `TrafficWarningShown`/`ExpiryWarningShown` reset when values recover). `SubscriptionRefreshCoordinator` applies the per-subscription server filter and sort and keeps the previous server list when the filter matches nothing; the 1-minute timer refreshes only subscriptions whose own interval (or the global one) is due. Per-subscription settings can be set when adding a subscription or later via the row context menu.
- Geo data: `Services/GeoDataUpdateService` updates `geoip.dat`/`geosite.dat` for Xray from Loyalsoldier/v2ray-rules-dat (backup + rollback), installed next to the active `xray.exe`; UI: Settings → Ядра → «Обновить geo-данные».
- Reliability: the view model reconnects on core crash, network change (`NetworkChange`) and system resume (`SystemEvents.PowerModeChanged`), with an 8-second guard after connect and a 10-second debounce; managers expose `LastConfigHash` (SHA-256, 12 chars, `Core/ConfigHash`) shown in the status bar and logged at core start.
- The app is single-instance (`App.TryAcquireSingleInstance`, named mutex + activation event); the elevated ElyTun handoff relaunch is exempt.
- Bundled versions: Xray 26.9.30, sing-box 1.14.2, tun2proxy 0.8.4 (local/untracked; updated in-app). Hysteria 2 (2.13.0) is optional and only downloaded through the core updater. `sing-box/sing-box.exe` is tracked. Release packaging also requires `tun2proxy\tun2proxy-bin.exe` and `helper\ElyProxy.Helper.exe`.
- New dependencies: YamlDotNet (Clash YAML), QRCoder (share QR), plus `System.IO.Pipes.AccessControl`/`System.ServiceProcess.ServiceController` in `ElyProxy.Helper` only.
- CI: `.github/workflows/ci.yml` builds, runs the xunit suite and the Pester release-script tests, then publishes and verifies the package layout (updater/helper/sing-box/22 rule-sets) on windows-latest (the sing-box `check` tests rely on the tracked `sing-box/sing-box.exe` and `Assets/RoscomVPN/`).

## UI conventions (Apple-style redesign)

- Theming is fully ours: `ThemeService` swaps the whole token dictionary by reassigning `ResourceDictionary.Source`, reads the system theme from `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme` + `SystemEvents.UserPreferenceChanged`, and picks `Tokens.HighContrast.xaml` when `SystemParameters.HighContrast` is set. WPF-UI's theme manager/watcher is deliberately not used.
- **WPF-UI 4.3.0 is still a `PackageReference` but nothing uses it any more** — no dictionaries are merged from it and no XAML references its controls (only a leftover unused `xmlns:ui` declaration in `MainWindow.xaml`). Don't reintroduce it as a theme/backdrop owner; it fights `ThemeService` over the window state.
- Every color/brush is a token referenced with `DynamicResource` — `StaticResource` on colors breaks live theme switching.
- Backdrop: `Interop/WindowBackdropInterop.Apply` uses `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` on Windows 11 and the composition accent (`SetWindowCompositionAttribute`) on Windows 10. It must run after the HWND exists (`ThemeService` hooks `SourceInitialized`), the window `Background` stays `Transparent`, and `ShellSurfaceBrush` toggles between `MaterialThinBrush` (translucent shell) and `Bg2Brush` (opaque) depending on the mode.
- Typography: WPF has no letter-spacing. Optical sizing is approximated with the `Segoe UI Variable Display`/`Text` variants plus `Typography.Kerning`; don't try to fake tracking with inserted spaces (it breaks copy and screen readers).
- Text adaptivity: a wrapping `TextBlock` must be width-constrained — never put one in a horizontal `StackPanel` (it measures children with infinite width, so the text clips instead of wrapping; this was a real bug in the sidebar status card, now a `Grid` with an `Auto`/`*` pair). Every `TextTrimming="CharacterEllipsis"` text in the shell carries a `ToolTip` with the full value. Both rules are locked by `MainWindowLayoutTests`.
- Server badge flags: WPF cannot render colour emoji, so `Services/FlagCatalog` parses a flag emoji (🇸🇪) or the leading two-letter code from the node name and maps it to a bundled PNG in `Assets/Flags` (embedded `Resource`, `pack://application:,,,/ElyProxy;component/Assets/Flags/<cc>.png`, public-domain flagcdn w80 set; aliases UK→GB, EL→GR). The `FlagImage` MultiBinding converter (registered in `Theme/Converters.xaml`) feeds the round badge `Image` (EllipseGeometry clip, UniformToFill) in `ServersView`/`ProfilesView`; when no flag matches, the existing code/monogram text shows through. `ServerBadgeMode` (Flag/Monogram/None) gates the whole slot. Add new flag files to `Assets/Flags` as lowercase ISO codes — the converter needs no list.
- `Radius.Card`/`Radius.Control`/`Radius.Small` are `CornerRadius`, not `Double` (using `Double` throws at load).
- A control derived from another custom control does **not** inherit its implicit style: `DefaultStyleKeyProperty.OverrideMetadata` does not propagate to derived types, so e.g. `ModeSelector` needs its own `Style TargetType="{x:Type controls:ModeSelector}"` (without it the control silently renders with zero height).
- A template child that is itself a `Control` takes `Foreground`/`Background` from its system default style, and that beats inherited values. Bind them explicitly in custom templates (`Foreground="{TemplateBinding Foreground}"` on the ComboBox's inner `ToggleButton`); otherwise e.g. ComboBox selection text stays system-default black in the dark theme.
- Motion: use `SpringAnimator.AnimateTo(...)` for anything gesture-driven or interruptible; storyboards are only for press feedback and short fades. Check `MotionPreferences.ReducedMotion` for opt-outs.
- Feedback: no `MessageBox` — use `DialogService.Current` (`ConfirmAsync`, `AlertAsync`, `Notify`). Both surfaces are our own controls: `Controls/SheetHost` (scrim + material card + spring) and `Controls/ToastHost` (top-right stack). WPF-UI's `ContentDialog`/`Snackbar` are not used at all. `DialogService` must be attached by `MainWindow` before use (it is, in the constructor).
- Settings explanations use `Controls/InfoHint` (ringed "i", themed tooltip from `Theme/Controls/Hints.xaml`) — put one next to any setting whose effect is not obvious (core choice, DPI, routing preset, per-app mode, helper service).
- Scrolling: `Controls/Behaviors/SmoothScroll` is attached to the template/page `ScrollViewer`s and springs the wheel; lists set `ScrollViewer.CanContentScroll="False"` so offsets are pixels — keep that pairing when editing list styles.
- The tray menu is `Views/TrayMenuWindow` (own WPF popup on right-click, closes on deactivate, forces foreground via `SetForegroundWindow`).
- The three exclusive connection modes are surfaced as one `ModeSelector` bound to the existing `SystemProxyEnabled`/`ProxyProEnabled`/`ElyTunEnabled` flags; the view model already enforces exclusivity.
- The window uses a custom title bar (`WindowStyle="None"` + `WindowChrome`); the window `Icon` and tray icon use the explicit `pack://application:,,,/ElyProxy;component/icon.ico` URI so they resolve outside the entry assembly.
- The journal is filtered **in the view**: `LogBox.Text` is not bound to `LogText` (the view model keeps the full text, `MainWindow.xaml.cs` applies search/level filtering). Don't re-add the binding.
- Row context menus are declared in `UserControl.Resources` with `x:Shared="False"` and receive the view model via `Tag="{Binding DataContext, RelativeSource={RelativeSource AncestorType=UserControl}}"` + `PlacementTarget.Tag`. Dropping `x:Shared` breaks reuse across rows.
- Sheets with inline validation implement `Services.ISheetValidation`; `Controls/SheetHost` binds its `PrimaryButton.IsEnabled` to `IsValid` (via `DialogService.ShowCustomAsync`), so the sheet cannot be submitted invalid.
- Loading placeholders: `Controls/SkeletonList` shown through the `BoolAndZeroToVis` multi-converter (`IsLoading` + collection count).
- High contrast: `Theme/Tokens.HighContrast.xaml` maps every token to `SystemColors`; `ThemeService` selects it when `SystemParameters.HighContrast` is true.

## Testing notes

- `TESTING.md` (Russian) is the full test plan: levels, coverage matrix, per-subsystem cases, environments, gap analysis and the manual QA checklist. Keep it in sync when adding features or tests.
- Tests instantiate builders directly (no mocks) and assert on generated JSON.
- `SingBoxConfigBuilderTests` shells out to `sing-box/sing-box.exe check` and locates the repo root by walking up to `ElyProxy.sln`, so tests fail if the committed `sing-box/sing-box.exe` is missing or the project is run from a copied output dir. They also assert the 22 bundled rule-sets under `Assets/RoscomVPN/` exist.
- `XrayConfigContractTests` validates generated configs with `xray run -test` and documents the bundled policy (VLESS without TLS only for private IPs/localhost). It silently returns when the untracked local `xray/` folder is absent, so CI only exercises the sing-box contract.
- Injectable test seams: `UpdateService` (`HttpClient` + updates directory), `CoreUpdateService` (`HttpClient` + cores root + version probe), `GeoDataUpdateService` (`HttpClient` + target directory). `UpdateServiceTests` cover the manifest/SHA/size/`.partial`; `CoreUpdateServiceInstallTests`/`GeoDataUpdateServiceTests` cover install rollback (broken core, bad SHA, incomplete archive, locked file). `PackageExtractorTests` cover the updater's zip-slip guard and `UpdaterCliTests` the updater CLI (`UpdaterArguments`/`InstallPreflight`); the test project references both subprojects. `HelperProtocolTests` cover the helper allowlist/protocol (`InternalsVisibleTo` from `ElyProxy.Helper`).
- No UI tests and no lint/format/typecheck tooling. UI changes are verified by building, then running the app (UAC) and checking: both themes, Mica/Acrylic fallback on Windows 10, reduced motion/transparency, sidebar sections, log drawer, sheets/toasts.
- Cheap pre-check without elevation: an STA smoke harness lives outside the repo at `%TEMP%\opencode\elyproxy-smoke` (`dotnet run --project ...\ElyProxySmoke.csproj`). It `ProjectReference`s `ElyProxy.csproj`, instantiates `ElyProxy.App`, and renders `MainWindow`, all sections, sheets, tray menu and controls off-screen. It asserts the theme-token switch (card/label colors), ComboBox text foreground across Dark→Light→Dark, shell-surface alpha, `ModeSelector` template/height, badges, spinner, toasts and sheets. Binding warnings are collected through a `PresentationTraceSources.DataBindingSource` listener; a clean run prints `RENDERED OK` with `TRACE_COUNT=0` and `CHECKS_FAILED=0`. It cannot run while the app is open (the single-instance mutex shuts the test instance down). If the temp folder is cleaned, recreate it from these checks — the checks are the contract.

## Gotchas

- `release-build/` and the root `xray/` folder are untracked local artifacts (hundreds of MB). `xray/`, `tun2proxy/` and `hysteria/` are gitignored; `.gitignore` also covers `bin/xray/*` binaries. `sing-box/sing-box.exe` is intentionally tracked. `dist/` is a stale committed build output; leave it alone. `publish/` is gitignored (local preview builds).
- Runtime binaries resolve relative to the app directory: xray from `xray/xray.exe`, `bin/xray/xray.exe`, or `xray.exe`; sing-box from `sing-box/sing-box.exe`; tun2proxy from `tun2proxy/tun2proxy-bin.exe` (falls back to `bin/tun2proxy/`). Local runs need xray binaries placed manually.
- Update manifest lives at `https://elysiumhub.org/updates/elyproxy/update.json`; `UpdateService` rejects non-HTTPS, other hosts, non-`.zip` URLs, and bad SHA-256. Deploy the ZIP first and `update.json` last.
- Parts of `Core/`, `Services/`, `Models/`, `ViewModels/` are decompiler output (tabs, explicit `using`s, `this.` prefixes, the `ReadOnlyArray.cs` `<>z__ReadOnlyArray` artifact at the repo root that decompiled code depends on). Match the surrounding file's style instead of reformatting; new files use 4 spaces.
- Process-layer awaits must use `ConfigureAwait(false)` (`ProcessManager`, `HelperProcessManager`, `ProcessManagerRouter`, manager `StopProcessAsync` wrappers): managers' `Dispose` blocks on them via `GetAwaiter().GetResult()` from the UI thread, and a context-captured continuation deadlocks the app (this actually happened with proxy-ping probes through the helper service). Probe cores (`ProbeCoreRunner`) deliberately use a local `ProcessManager`, not the helper router.
- XAML with Cyrillic must be saved as UTF-8 (no BOM is fine, CRLF like the existing files).
- `README.md` (Russian) is the user-facing doc; its project-structure section is stale and omits newer files.

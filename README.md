ElyProxy собирает подписки, серверы и правила подключения в одном приложении: от локального SOCKS5 до ElyTun для системного трафика. Найдите подходящий сервер, проверьте его доступность и выберите, какие сайты и приложения подключать через прокси.

Если одновременно включённый Zapret мешает YouTube или Discord в ElyTun,
откройте **Настройки → ElyTun → Совместимость с Zapret → Настроить совместимость**.
Подтвердите запрос Windows, затем переподключите VPN и голос Discord. Zapret
продолжит работать на физических сетевых адаптерах, а пакеты внутри ElyTun
будут исключены из его обработки. Кнопка **«Отменить настройку»** восстанавливает
исходную конфигурацию. Поддерживается Zapret, установленный службой `zapret`
с прямым запуском `winws.exe`; запуск через `.bat` без службы не изменяется.
После добавления сетевого адаптера или переустановки Zapret повторите настройку.

Переключатель **«Блокировать Torrent»** находится только в настройках, в группе «Защита подписки».
Он сохраняется между запусками и принудительно завершает известные торрент-клиенты
сразу после включения и при повторном запуске (проверка каждую секунду), даже без VPN.
Загрузки прерываются. Контроль работает, пока ElyProxy открыт, в том числе в трее.
Перед подключением выполняется дополнительная проверка: если клиент невозможно
закрыть, подключение отменяется, выводятся уведомление и запись в журнале.

> **Для подключения нужна ваша подписка или конфигурация сервера.** ElyProxy — клиент; приложение само по себе не выдаёт VPN-серверы или доступ к ним.

## Установка

**Требования:** Windows x64 и **.NET 8 Desktop Runtime x64**. Клиент использует WPF; сборка для Linux/macOS в этом репозитории не предусмотрена.

1. Откройте **[последний релиз](https://github.com/CrackKO/ElyProxy/releases/latest)**.
2. В разделе **Assets** скачайте `ElyProxy-X.Y.Z-win-x64.zip` — готовую программу, а не архив `Source code`.
3. Распакуйте **весь архив** в постоянную папку, например `%LocalAppData%\Programs\ElyProxy`.
4. Запустите `ElyProxy.exe`. Если Windows попросит .NET, установите [**.NET 8 Desktop Runtime для Windows x64**](https://dotnet.microsoft.com/en-us/download/dotnet/8.0) и повторите запуск.

Сохраняйте папки ядер, `updater`, `helper` и `Assets` рядом с программой. Перенос одного `ElyProxy.exe` не заменяет распаковку полного пакета.

> Для обычного запуска права администратора не нужны. ElyTun запросит повышение прав при включении; необязательная служба-помощник позволяет затем подключать TUN без повторных запросов UAC.

## Первое подключение

1. На экране **Серверы** нажмите **＋ Добавить → Добавить подписку** и вставьте ссылку от своего провайдера. Для отдельной ссылки выберите **Добавить сервер вручную**.
2. Дождитесь загрузки серверов. При необходимости используйте поиск или фильтры.
3. В панели подключения выберите режим: **Proxy Lite**, **Proxy Pro** или **ElyTun**.
4. Выберите сервер и нажмите **Подключить**. Двойной щелчок или `Enter` также подключает выбранный сервер.
5. Проверьте нужный сайт или приложение. Если что-то не работает, нажмите **Диагностика** на экране серверов.

Для приложения с собственной настройкой прокси укажите **SOCKS5**, адрес `127.0.0.1`, порт `1080` (по умолчанию). Порт можно изменить в настройках ElyProxy.

## Режимы подключения

| Режим | Как работает | Когда выбрать |
| :-- | :-- | :-- |
| **Proxy Lite** | Xray + системный PAC Windows. Доменные правила определяют прямой маршрут. | Для браузера и приложений, которые поддерживают системный PAC. |
| **Proxy Pro** | sing-box + системный HTTP/HTTPS/SOCKS-прокси. Поддерживает правила по приложениям для трафика, поступающего в прокси. | Если нужна совместимость с протоколами sing-box и более гибкие правила. |
| **ElyTun** | TUN-интерфейс и системная маршрутизация. Ядро выбирается в настройках. | Для приложений, которые не используют системный прокси. Нужны права администратора или работающая служба-помощник. |

Режимы взаимоисключаются. Системный прокси охватывает приложения, которые его используют; ElyTun направляет системный трафик с учётом исключений и правил. **Proxy Lite не поддерживает маршрутизацию по приложениям.**

[Разделение трафика, выбор ядра и служба-помощник →](docs/USER-GUIDE.md#маршрутизация-и-elytun)

## Протоколы и ядра

| Ядро | Поддерживаемые протоколы | Где используется |
| :-- | :-- | :-- |
| **[Xray-core](https://github.com/XTLS/Xray-core)** | VLESS, VMess, Trojan, Shadowsocks, SOCKS, HTTP | Proxy Lite, Xray TUN, бэкенд tun2proxy |
| **[sing-box](https://github.com/SagerNet/sing-box)** | Протоколы выше, Hysteria2, TUIC, AnyTLS, SSH, WireGuard, NaiveProxy, ShadowTLS | Proxy Pro, ElyTun, бэкенд tun2proxy |
| **[Hysteria 2](https://github.com/apernet/hysteria)** | Hysteria2 | Отдельный движок Hysteria2 и Hysteria TUN; устанавливается через обновление ядер |
| **[tun2proxy](https://github.com/tun2proxy/tun2proxy)** | Работает поверх локального SOCKS/mixed-бэкенда | Альтернативный TUN-провайдер |

**Совместимость зависит и от транспорта:** VLESS Encryption, xhttp и mKCP требуют Xray; NaiveProxy — `libcronet.dll` рядом с sing-box; ShadowTLS — конфигурацию цепочки Shadowsocks + ShadowTLS. Для WireGuard и таких цепочек используйте поддерживаемый JSON/Clash-импорт. Приложение сообщает, когда узел несовместим с выбранным ядром.

## Проверка серверов

| Проверка | Что показывает |
| :-- | :-- |
| **TCP-пинг** | Доступность адреса и порта сервера. Сам по себе не подтверждает работу прокси. |
| **Proxy GET** | Результат HTTP GET через временный прокси; адрес проверки задаётся в настройках. |
| **ElyTurbo** | Доступность Discord, Telegram, YouTube, Spotify, GitHub и Gmail; выбор лучшего кандидата по результатам. |
| **ElyHard** | Повторные запросы к сервисам через временный прокси, оценка стабильности и задержки. |

Выберите тип в настройках, затем нажмите **Проверить задержку**. Проверка охватывает весь список, включая серверы, скрытые фильтрами. Это результаты конкретных проверочных запросов, а не гарантия работы всех функций сервисов.

## Полезно знать

- **Свои правила** по умолчанию отправляют российские доменные зоны напрямую. Если сайт открывается без прокси, проверьте разделение трафика.
- **«Блокировать Torrent» завершает обнаруженные процессы торрент-клиентов**, пока ElyProxy открыт, даже без VPN. Это необязательная настройка, а не сетевой фильтр BitTorrent. [Подробности →](docs/USER-GUIDE.md#защита-подписки)
- Конфигурации и настройки хранятся в `%AppData%\ElyProxy\`. Перед переносом или переустановкой сохраните эту папку.
- Если после аварийного закрытия остался системный прокси, его можно выключить в настройках прокси Windows. [Решение частых проблем →](docs/USER-GUIDE.md#решение-проблем)

### Выходной прокси (1.4.5 DEV)

В **Настройки → Сеть → Выходной прокси** задайте второй SOCKS5/HTTP/HTTPS-прокси и включите цепочку при отключённом соединении. Затем выберите основной сервер и подключитесь. Маршрут для проксируемого трафика: компьютер → основной сервер → выходной прокси → сайт. Поддерживаются Proxy Pro и ElyTun на sing-box/Xray. При отказе второго узла резервного выхода через первый нет. Прямые исключения маршрутизации продолжают действовать. Настройка выключена по умолчанию; HTTP/HTTPS — только TCP, SOCKS5 UDP зависит от провайдера.


### Надёжность соединения и активный сервер (1.4.5 DEV)

Активный сервер закреплён над таблицей до отключения. Поиск, фильтры и обновление или удаление подписки не скрывают текущее соединение. Если параметры сервера в подписке изменились, закреплённая строка показывает параметры уже открытой сессии.

После установки этого DEV-билда обновите службу-помощник через **Настройки → ElyTun → Установить службу** при отключённом соединении. Новый протокол подтверждает остановку и очистку сетевой сессии. Старой службе запуск новых ядер запрещается с пояснением.

При ошибках доступны **Настройки → Сеть → Проверить состояние сети** и постоянный журнал `%LocalAppData%/ElyProxy/lifecycle.log`. Не требуется начинать диагностику с полного сброса сетевых настроек: клиент проверяет завершение своих процессов, локальный порт и восстанавливает ресурсы только принадлежащих ему новых TUN-сессий. Старые неизвестные адаптеры и сторонние VPN автоматически не удаляются.


### Auto, DPI и безопасное переключение

В настройках доступен Auto для TUN и для прокси-режимов: выбирается установленное совместимое ядро, обычно sing-box; xhttp, mKCP и VLESS Encryption требуют Xray. Старые сохранённые настройки остаются явными. Причина выбора показывается в настройках; несовместимая конфигурация проверяется до остановки работающего соединения.

Параметры DPI разделены по ядрам. Выберите сервер и Xray/sing-box в разделе DPI. Для каждого сервера сохраняются отдельные параметры обоих ядер. Новые дополнительные методы не включаются автоматически. После изменения ядра или DPI нажмите «Применить настройки соединения». При неудачном переключении приложение пытается один раз восстановить предыдущую сессию.

Подключение проверяет локальный SOCKS, а в TUN — собственный адаптер и маршруты, затем HTTPS через выбранный путь. Наличие стороннего VPN само по себе не подтверждает готовность ElyTun. После отключения восстанавливаются принадлежащие ElyProxy настройки. Ошибка очистки требует повторного отключения или выхода; глобальный сброс сети не используется.

Изменения требуют дополнительной сетевой приёмки в изолированной Windows VM; её матрица приведена в TESTING.md.


### ElyTurbo и ElyHard (1.4.6)

Это проверки реального HTTPS-выхода через временный локальный прокси, а не обычный TCP-ping. Ядро выбирается той же политикой, что при подключении; используются сохранённый DPI-профиль сервера и выходная прокси-цепочка. Системные прокси, DNS и маршруты не меняются. При работающем стороннем VPN проверяется доступ через него: результат не доказывает доступность сервера напрямую через провайдера.

- **ElyTurbo**: один запуск ядра, две контрольные HTTPS-точки и три сервиса. Один запрос на точку, без загрузки файла; настраиваемое число серверов одновременно и до двух запросов на сервер. Это быстрый отбор кандидатов.
- **ElyHard**: два независимых запуска ядра; три раунда для двух контрольных точек и шести веб-сервисов; новые HTTPS-соединения без повторного использования пула; две полные загрузки по 1 МиБ через Cloudflare Speedtest API. С 1.4.7 одновременно проверяется несколько серверов по настройке «Серверов одновременно», до двух HTTP-запросов на сервер; нагрузочные загрузки выполняются по одной. Проверка ограничена тремя минутами на сервер (запуск и очистка процесса дожидаются подтверждения). Полный успешный результат — 26/26 проверок; нагрузочная часть расходует 2 МиБ на сервер, плюс небольшие ответы сайтов. Большая подписка может проверяться долго.
- HTTP 403/429/451, перенаправление, неправильная страница и незавершённая загрузка не считаются успешным открытием сервиса. Ограничение сайта отмечается отдельно и само по себе не доказывает неисправность сервера.
- С 1.4.7 результаты сортируются по рейтингу качества, а прежний диагностический вердикт сохраняется в подробном отчёте.
- «Медленно»: p95 больше 2500 мс либо хотя бы одна успешная загрузка медленнее 2 Мбит/с; «Нестабильно»: не прошла контрольная/нагрузочная проверка или разброс успешных HTTPS-задержек превысил 1500 мс. Это диагностические пороги, а не требования всех приложений.

Наведение на результат показывает подробности; «Отчёт проверки» копирует весь отчёт. «Остановить проверку» отменяет запросы и ожидает остановки временных ядер. Выбранный сервер не заменяется автоматически. Старые результаты других режимов не следует сравнивать напрямую: медиана нового теста включает SOCKS, TLS и получение части содержимого, а не только TCP-handshake.

Даже «HTTPS проверен» не гарантирует голос Discord, UDP/QUIC, игровой трафик, авторизацию, видео или исправность TUN-маршрутов. Проверка страницы YouTube не является тестом видеопотока. Отдельное ядро Hysteria пока отмечается «не подтверждено»; ядро sing-box для Hysteria2 проверяется. Смена сети, сервера, DPI или ядра требует нового теста. Результаты относятся к времени и конфигурации в отчёте.

Проверка загрузки использует документированный Cloudflare Speedtest API: https://github.com/cloudflare/speedtest .


### Качество и параллельная проверка (1.4.7)

Число раундов/запусков, адреса, проверка содержимого, размер файлов, паузы и тайм-аут каждого запроса сохранены. Ускоряется обход списка: настройка «Серверов одновременно» теперь применяется и к ElyHard. Предел для ElyTurbo/ElyHard — 16, дополнительно учитываются CPU (до двух проб на логический процессор) и свободная RAM (оценочный бюджет 384 МиБ на пробное ядро, около 1 ГиБ оставляется свободным). Это ограничитель параллельности, а не жёсткая квота памяти: реальный расход ядра зависит от конфигурации. Фактическое число параллельных серверов показывается в прогрессе и отчёте. Нагрузочные загрузки ждут единого слота; время ожидания слота не расходует трёхминутный бюджет активной проверки. Сами HTTP-тайм-ауты не увеличены. Больше RAM не ускоряет удалённый сервер; рост параллельности может упереться в пропускную способность сети.

В строке сервера теперь две короткие строки: «B 89 · Можно*» и «620 мс HTTPS · ≥8,4 Мбит/с». Подробности и счётчики остались в подсказке и отчёте. A/B — можно подключаться по результатам HTTPS-пробы; C/D — запасной вариант (медленно, мало доступных сайтов или перебои); F — нет успешных контрольных ответов, не рекомендуется; ? — недостаточно данных. Звёздочка означает ограничения отдельных сайтов, а не неисправный прокси. Красный применяется к отсутствию контрольных ответов, жёлтый — к оговоркам, серый — к неполной проверке. Одна большая задержка не доказывает недоступность.

Рейтинг 0–100 — наша сравнительная эвристика, **не процент вероятности**: контрольные запросы 40 баллов, полные загрузки 25, доступность сайтов 15, время HTTPS 10, нижняя оценка скорости 10. A: от 90; B: от 75; C: от 55; D: ниже 55. При пропусках сайтов рейтинг не выше 89; при отказах транспорта, нестабильности повторов одного и того же сайта или недоступности большинства сайтов — не выше 69; при медленной передаче — не выше 74. Turbo не измеряет скорость и остаётся предварительным результатом не выше B/85. Рейтинг не отменяет конкретные отрицательные результаты в отчёте.

Добавлены сортировки «По качеству» (балл, скорость, задержка) и «По скорости». Старая сортировка «По задержке» оставлена отдельно. Стабильность оценивается по повторам одной цели: разницу между быстрым и медленным разными сайтами нельзя считать сетевым джиттером.

TCP-шкала 100/200 мс больше не используется для ElyTurbo/ElyHard. Полная проба включает SOCKS, TLS и часть тела. Для оценки отклика использованы ориентиры 800/1800 мс; они вдохновлены приблизительными границами браузерного TTFB, но наша проба не равна TTFB. См. https://web.dev/articles/ttfb .


### Изменения 1.4.8

Проверки ElyTurbo/ElyHard используют независимый от переключателя режима локальный прокси:
явно выбранное ядро прокси либо Auto для старого значения «Как в прежней версии».
Сохраняются DPI сервера и выходная цепочка. Выбор ElyTun больше не меняет ядро проверки.
Результат подтверждает локальный прокси-путь, а не запуск TUN или работу правил PAC.
Активный сторонний VPN по-прежнему влияет на фактический сетевой путь проверки.

Фоновый журнал: `%LocalAppData%/ElyProxy/lifecycle.log`, предыдущий файл — `.previous`.
Запись выполняется в ограниченной фоновой очереди; при перегрузке часть сообщений может быть потеряна.
Размер каждого файла ограничивается ротацией около 10 МиБ. Записываются переходы состояний,
процессы и сообщения ядер, результаты HTTPS-проб, метаданные запросов подписок и обновлений,
цепочки типов исключений, коды HTTP/TLS/сокетов и стек. При ошибке HTTP сохраняются текущие
DNS/шлюзы активных адаптеров и признаки прокси/PAC (только чтение).
HTTP-журнал не записывает заголовки, тела и пути URL; ссылки и известные поля секретов маскируются.
Журнал может содержать адреса сетевых узлов и метаданные локальной сети; он остаётся на компьютере.

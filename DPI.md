# Настройки DPI — DEV 1.4.4

Все новые возможности запускаются пользователем в **Настройки → Обход DPI**.
На новой установке фрагментация, TLS-записи, noise и spoofing выключены;
отпечаток берётся из подписки. Существующие настройки сохраняются.
Автоматического запуска подбора при старте, смене сети или обрыве нет.

## Профили

Выбор в списке ничего не меняет. «Применить профиль» сохраняет параметры для
следующего подключения, без перезапуска работающего туннеля. Ручные переключатели
старого блока по-прежнему применяют изменения к активному подключению.
Профили отключают noise/spoofing, но сохраняют отдельно выбранный TLS-отпечаток.
Настройки общие для подключений; автоматической привязки к оператору/узлу нет.

| Профиль | Xray | sing-box |
|---|---|---|
| Без обработки DPI | Без фрагментации | Без фрагментации и TLS-записей |
| TLS-записи | Не применяется | Только `record_fragment` |
| Мягкая фрагментация | 200–400 байт, 1–3 мс | `fragment`, fallback 1 мс |
| Сбалансированный | 100–200 байт, 10–20 мс | `fragment`, fallback 10 мс |
| Мелкие фрагменты | 50–100 байт, 5–10 мс | Не применяется |
| Увеличенная пауза | 100–200 байт, 30–50 мс | `fragment`, fallback 30 мс |
| Записи + фрагментация | Не применяется | Оба механизма, fallback 10 мс |
| Первые записи TCP | Первые 3 записи, 100–200 байт, 10–20 мс | Не применяется |

Это экспериментальные кандидаты, а не измеренные пресеты конкретных операторов.
sing-box сам определяет сегментацию; диапазон длины Xray не переносится в него.
`fragment_fallback_delay` — резервная задержка, а не обязательная пауза каждого
фрагмента. Старое «Авто» переименовано в «Стандартный»: это фиксированный профиль.
Разделение TLS-записей теперь работает независимо от TCP-фрагментации.

## Ручной подбор

1. Выбрать сервер, отключить VPN, открыть настройки DPI.
2. Выбрать ядро: Xray для Proxy Lite/Xray TUN; sing-box для Proxy Pro/sing-box
   ElyTun. Для tun2proxy выбрать ядро его SOCKS-бэкенда.
3. Нажать «Начать подбор». Нужен VLESS/VMess/Trojan с TLS/REALITY через
   поддерживаемый TCP-транспорт. QUIC, mKCP и другие протоколы исключены.
4. Временные локальные ядра проверяют совместимые профили последовательно,
   не меняя маршруты и прокси Windows. Xray-пробы теперь действительно получают
   DPI-параметры, без создания TUN-интерфейса.
5. HTTPS endpoint `www.gstatic.com/generate_204` и
   `cp.cloudflare.com/generate_204` проверяются дважды каждый. HTTP-соединение
   закрывается после каждого запроса. Успех — валидный HTTPS и код 204.
   Тайм-аут запроса 5 секунд, общий лимит 4 минуты, доступна отмена.
   Пробные ядра освобождаются при выходе. Подключение VPN на время подбора
   блокируется, чтобы не измерять доступность через уже работающий туннель.
6. Рекомендация требует 4/4 успехов. Если без обработки тоже 4/4, рекомендуем
   её не включать; иначе выбираем минимальную среднюю задержку среди прошедших.
   Рекомендацию нужно отдельно применить. Неуспех/отмена не меняют настройки.

Результат показывает достижимость двух сервисов через данный сервер и ядро сейчас.
Это не замер скорости, не долгосрочная проверка устойчивости и не доказательство
DPI: проверочный сервис может быть сам недоступен. Строгий IP-белый список или
отключение связи требуют доступной точки входа; клиент её не создаёт.

## Отпечаток TLS

«Как в подписке» (по умолчанию), Chrome, Firefox, Safari, Edge. Применяется при
следующем подключении к TLS/REALITY в Xray и sing-box. Не меняет SNI, сертификат,
ключи REALITY или объект узла. Это форма ClientHello, а не полноценный браузер
и не дополнительное шифрование. Для QUIC и самостоятельного ядра Hysteria
эти параметры не применяются.

## Основания и следующие этапы

Изучены официальные контракты на 11.10.2026:
- [Xray Freedom: fragment/noises](https://xtls.github.io/config/outbounds/freedom.html)
- [sing-box TLS: fragment, record_fragment, spoof, uTLS](https://sing-box.sagernet.org/configuration/shared/tls/)
- [REALITY и совместимость транспортов](https://xtls.github.io/ru/config/transports/reality.html)

Документация sing-box рекомендует сначала пробовать TLS-записи и предупреждает
об ограничениях фрагментации и имитации браузера через uTLS. Поэтому агрессивность
обработки автоматически не увеличивается. Spoofing/noise остаются отдельными
экспертными параметрами: универсальный SNI/шумовой пакет без измерений не выбран.
ECH, NaiveProxy и альтернативные транспорты требуют серверной конфигурации;
их нельзя включить только клиентом поверх произвольной подписки.
Следующие этапы: хранение результатов по узлу/сети, диагностика этапа сбоя,
резервные транспорты, предоставленные сервером.


В настройках DPI теперь можно выбрать сервер независимо от главного экрана. Без отдельного выбора используется текущий выбранный сервер. Результаты проверки показаны таблицей: выбор строки выбирает профиль, но только «Применить профиль» сохраняет его для следующего подключения. Расширенные ручные параметры находятся в раскрывающемся блоке; поиск настроек умеет раскрывать его автоматически.
